Topic: Django Signals

Solution to question 1

By default, Django signals are synchronous. This means:

  • The caller waits until the signal handler finishes execution.
  • Execution is blocking.
  • The next line executes only after the signal handler completes.
  • The demonstration is done when the following link is accessed: Demo1.
  • When the above link is opened the a new object is added in the database and a signal is triggered
  • Adding a delay of 5 seconds in the signal handler forces the sigal to pause for 5 seconds.
  • The response is displayed in the link only after 5 seconds.

Solution to question 2

By default, Django signals run in the same thread as the caller.

  • The Caller thread and Signal thread are printed in the terminal.
  • Both thread Ids match showing that both are running in the same thread.

Solution to question 3

By default, Django signals run in the same database transaction as the caller.

  • The demonstration is done when the following link is accessed: Demo2.
  • On clicking this link a database transaction is triggered.
  • Signal executes during the transaction.
  • But the transaction is intentionally rolled back.
  • Since the transaction is rolled back the object is not created in the database.
  • After roll back the database is queried for the object and it returns 0.
  • This shows that the signal paticipated in the same transaction.
  • When the transaction rolled back, the database change also was rolled back.
